# Marketplace review — local only

Public routes: `/`, `/services`, `/marketplace/vendors`, `/marketplace/financing`,
`/marketplace/profiles/[id]`, `/how-it-works`, `/join-network`.

Existing routes and actions remain. The original homepage is preserved beside this file.
The original video, account entry buttons, Sturdi Guy and chat remain in place.

## Data and publishing

`MarketplaceListing` is a new, separate table. No production schema changes have been
applied. `prisma/marketplace-additive.sql` is the additive SQL for review before release.
Run it first against an isolated PostgreSQL test database populated with test users,
then regenerate Prisma. Do not run seeds or schema resets against the live database.
This project previously had no migration history; do not introduce a partial Prisma
migration history or run `migrate deploy` without first planning a baseline.

Until that table exists, directories explicitly report unavailable and existing
profile pages retain their original content. This is not an empty-vendor result.
The partner profile editor appears after the table is available.

Approved vendors and financing partners can save their own listing in Company Profile.
Publishing is opt-in. Account email and phone are not copied into public fields.
Only published listings owned by a currently approved partner of the matching role
are publicly visible. Images are partner-hosted HTTPS URLs, up to eight photos.
Unpublished, rejected and pending partners are excluded, including direct profile URLs.

## Marketplace boundaries

Search uses GET requests and reads only; results are alphabetical. City/state/ZIP
matching uses partner-listed area text, not geocoding or radius matching. Listings
must include the locations they want to be found for. Contact links go directly to
the selected business. No request, assignment, lead distribution, billing, click fee,
rotation, or notification is generated by a marketplace search or profile view.
Financing is a separate directory with non-lender/approval disclosures.

## Review before release

- Apply additive SQL to an isolated test database; exercise save, draft, publish and unpublish.
- Confirm each partner can modify only their own listing; reject homeowner/admin submissions.
- Confirm unpublished/rejected listings cannot be fetched through public URLs.
- Check category and location combinations, zero results, database outage, and invalid inputs.
- Check phone/email/website links and image display at mobile and desktop widths.
- Confirm existing login, portals, chat, billing and request tools still operate independently.
- Obtain deployment approval before changing the production database or publishing code.
